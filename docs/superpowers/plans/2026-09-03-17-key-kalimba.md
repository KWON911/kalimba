# 17-Key Acoustic Kalimba Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a responsive, playable 17-key C-major kalimba web application with low-latency Web Audio playback.

**Architecture:** A typed note dataset drives UI ordering, display labels, keyboard mappings, and fallback frequencies. Focused hooks encapsulate audio, keyboard, and orientation behavior; presentational components render the instrument and controls; `App` coordinates user-facing state. Audio resources use refs and every note creates a new source so chords and rapid repeats overlap naturally.

**Tech Stack:** React 18, Vite, TypeScript, CSS, Web Audio API; no UI or audio packages.

## Global Constraints

- Use React + Vite + TypeScript and native CSS only; do not add UI/audio dependencies.
- The 17 visual tine positions and keyboard mapping exactly match the approved design specification.
- Use `/sounds/<NOTE>.wav` when present and an oscillator fallback if each individual sample is unavailable.
- Resume `AudioContext` only within user gesture paths.
- Support Pointer Events, independent pointer IDs, mouse, keyboard chords, and ignored key-repeat.
- Default master volume is 80%; default labels are number + note name; haptics default off.
- Keep the playing surface touch-safe with `touch-action: none` without disabling page accessibility globally.
- Keep excluded features out of scope: song mode, MIDI, recording, accounts, Supabase, uploads, and autoplay.

- `package.json`, Vite and TypeScript configuration: project scripts and compiler setup.
- `src/types/kalimba.ts`: shared note and label-mode types.
- `src/data/notes.ts`: canonical 17-key placement data and keyboard lookup.
- `src/hooks/useKalimbaAudio.ts`: AudioContext lifecycle, loading, gain control, sample playback, oscillator fallback.
- `src/hooks/useKeyboardControls.ts`: global keyboard event lifecycle.
- `src/hooks/useOrientation.ts`: media-query orientation state.
- `src/components/KalimbaKey.tsx`: one accessible tine.
- `src/components/Kalimba.tsx`: rendering, pointer tracking, and glissando hit processing.
- `src/components/Controls.tsx`: volume, labels, haptics, fullscreen controls.
- `src/components/PortraitNotice.tsx`: narrow portrait guidance.
- `src/App.tsx`, `src/main.tsx`, `src/styles.css`: orchestration, mounting, and responsive instrument styling.

### Task 2: Implement fault-tolerant Web Audio playback

**Files:**
- Create: `src/hooks/useKalimbaAudio.ts`
- Modify: `src/App.tsx`

**Interfaces:**
- Consumes: `KalimbaNote`, `KALIMBA_NOTES`.
- Produces: `useKalimbaAudio(): { playNote(note: KalimbaNote): Promise<void>; setVolume(value: number): void; loadingState: 'idle' | 'loading' | 'ready' }`.

- [ ] **Step 1: Implement lazy context creation and master gain**

Create `AudioContext`, `GainNode`, decoded-buffer `Map<string, AudioBuffer>`, and loading-state refs. Create and resume context only in `playNote`; apply volume to `masterGain.gain` with `setTargetAtTime`.

- [ ] **Step 2: Preload every sample independently after first interaction**

Fetch and decode each `note.file`; retain successful buffers and catch failures per file without rejecting the complete preload operation.

- [ ] **Step 3: Play sample or oscillator fallback per input**

For a buffer, connect a fresh `AudioBufferSourceNode` to master gain and call `start()`. Otherwise create a sine oscillator plus short per-note gain envelope, connect to master gain, and schedule stop. Never reuse or prematurely stop a source.

- [ ] **Step 4: Run production build**

Run: `npm run build`

Expected: all audio hook types compile.

- [ ] **Step 1: Render all 17 tines from data**

Each key renders number/note labels according to `LabelMode`, keyboard character, `aria-label="C4, 숫자 1, 키보드 S"` equivalent data, a native button role, and a CSS custom property based on `lengthRatio`.

- [ ] **Step 2: Track independent pointers and play on down**

Maintain `Map<number, string>` pointer-to-note plus `Map<string, Set<number>>` active pointers per note. On `pointerdown`, capture pointer, call `onPlay` first, mark only that pointer active, and optionally vibrate for 8ms when enabled.

- [ ] **Step 3: Implement safe glissando and cleanup**

On pointer movement, hit-test the element at coordinates with `closest('[data-note]')`. When a pointer enters a different note, clear its prior note, play the new note once, and mark it active. On up/cancel/leave clear that pointer only.
